# Spam Detector for YouTube Comments (ML ล้วนๆ)

ระบบตรวจ spam ในคอมเมนต์ YouTube ด้วย **โมเดล ML ล้วนๆ** ไม่มีกฎให้คะแนนและไม่มี threshold ของข้อความซ้ำนอกโมเดล

โมเดล (`ml/`) คือ Logistic Regression ที่ดู 2 อย่างพร้อมกัน
1. **เนื้อหาข้อความ** TF-IDF แบบ char n-gram (1–4)
2. **จำนวนครั้งที่ข้อความนั้นซ้ำ** (`app/duplicates.js` นับข้อความเดียวกัน ไม่สนตัวพิมพ์/เครื่องหมาย/ลิงก์/timestamp ในคอมเมนต์ของวิดีโอเดียวกัน) ส่งเข้าโมเดลเป็น feature 2 ตัว คือ "ซ้ำหรือไม่" กับ log(จำนวนครั้ง, สูงสุด 20)

## วิธีตัดสิน

spam เมื่อ **`ML ≥ ML_THRESHOLD`** (ค่าเริ่มต้น 0.5) อย่างเดียว ข้อความซ้ำไม่ได้เป็น spam อัตโนมัติ แต่ซ้ำแล้วจะเป็น spam หรือไม่ ขึ้นกับสิ่งที่โมเดลเรียนจากป้ายที่ติดไว้
ถ้าเรียกโมเดลไม่ได้ ตอบ HTTP 503 พร้อมข้อความชัดเจน (ไม่แอบถอยไปใช้อย่างอื่น)

ตัวอย่าง `.env`: `ML_THRESHOLD=0.4` (ลด threshold = จับได้มากขึ้น แต่ผิดพลาดมากขึ้น) ถ้าตั้งค่าผิดรูปแบบ เซิร์ฟเวอร์จะไม่เริ่มทำงานและบอกสาเหตุ
(ตัวแปร `DUP_THRESHOLD` เดิมไม่มีผลแล้ว) หน้าเว็บแสดงป้าย "ข้อความซ้ำ N ครั้ง" เป็นข้อมูลประกอบเท่านั้น

## โครงสร้างไฟล์

```
ml/                  ส่วน AI (Python)
  text_utils.py      clean() ตัวเดียวที่ใช้ทั้งตอนเทรนและทำนาย + ที่อยู่ไฟล์โมเดล
  train.py           เทรนโมเดล (ข้อความ + จำนวนซ้ำ) -> models/spam_model.joblib + models/metrics.json
  predict.py         ทำนายไฟล์ .jsonl / .csv -> data/predicted.jsonl (นับข้อความซ้ำด้วย node)
  ml_predict.py      สะพานให้ server.js เรียก (stdin/stdout เป็น JSON รับ [{text, dupCount}])
  evaluate.py        เทียบโมเดลที่ไม่ดูการซ้ำ / ที่ดูการซ้ำ บนข้อมูลที่ติดป้าย (out-of-fold)
models/
  spam_model.joblib  โมเดลที่เทรนแล้ว
  metrics.json       ผลวัดตอนเทรน        evaluation.json  ผลเทียบ
data/
  to_label.csv       ข้อมูลที่ติดป้ายแล้ว (text, label)   comments.jsonl  คอมเมนต์ดิบ
  dup_to_label.csv   ข้อความที่ซ้ำ ให้เติมป้ายเอง (ทับป้ายใน to_label.csv ตอนเทรน)
app/                 เว็บ (Node.js): server.js, duplicates.js (นับข้อความซ้ำ), decide.js (ML >= threshold), public/index.html
tests/               เทสต์: decide.test.mjs, server.test.mjs (Node) และ test_ml.py (Python)
tools/               collect_comments.js (ดึงคอมเมนต์), make_to_label.py, make_dup_to_label.py, run_dups.mjs
```

## ติดตั้ง

```bash
pip install -r requirements.txt     # Python 3.10+
npm install                         # Node.js 20.12+ (ใช้กับเว็บ, tools/ และตอนเทรนเพื่อนับข้อความซ้ำ)
cp .env.example .env                # ใส่ YT_API_KEY ของตัวเองใน .env (ใช้กับเว็บ/ดึงคอมเมนต์เท่านั้น)
```

## วิธีใช้

| ต้องการ | คำสั่ง |
|---|---|
| เทรนโมเดลใหม่ | `python ml/train.py` |
| ทำนายไฟล์คอมเมนต์ | `python ml/predict.py data/comments.jsonl` |
| เทียบโมเดลไม่ดู/ดูการซ้ำ | `python ml/evaluate.py` |
| เปิดเว็บ | `npm start` แล้วเปิด http://localhost:3000 |
| ดึงคอมเมนต์ใหม่ | `npm run collect` |
| สร้างไฟล์ให้ติดป้าย | `python tools/make_to_label.py` |
| สร้างไฟล์ติดป้ายเฉพาะข้อความซ้ำ | `python tools/make_dup_to_label.py` |
| รันเทสต์ทั้งหมด | `npm run test:all` (หรือแยก `npm test` / `npm run test:py`) |

ใช้ในโค้ด Python:
```python
from ml.predict import predict_texts   # (รันจากโฟลเดอร์หลัก หรือเพิ่ม ml/ ใน sys.path)
predict_texts(["สนใจงานแอดไลน์ @abc", "คลิปดีมาก"])   # -> [ความน่าจะเป็น spam, ...]
```

### วงจรปรับปรุงโมเดล
`npm run collect` → `python tools/make_to_label.py` → เติมคอลัมน์ `label` (spam / normal) → `python tools/make_dup_to_label.py` → เติมป้ายข้อความที่ซ้ำ → `python ml/train.py` → `python ml/evaluate.py`

### ติดป้ายข้อความที่ซ้ำ (`data/dup_to_label.csv`)
ไฟล์นี้รวมเฉพาะข้อความที่ซ้ำ ≥ 2 ครั้งในวิดีโอเดียว เติมคอลัมน์ `label` เป็น `spam` หรือ `normal` (ติดที่ตัวข้อความ)

| ซ้ำเพราะ | ป้าย |
|---|---|
| โพสต์ก็อปวาง/โปรโมต/บอท/ชวนติดต่อ/ปั่นจำนวน | `spam` |
| บังเอิญตรงกัน เช่น "ขอบคุณครับ", timestamp "1:23", อีโมจิเดี่ยวๆ | `normal` |
| ไม่แน่ใจ | เว้นว่าง (ใช้ป้ายเดิมใน `to_label.csv`) |

`python ml/train.py` อ่านไฟล์นี้เองและให้ป้ายในนั้นทับป้ายเดิม พร้อมแจ้งจำนวนที่เปลี่ยน และแสดงน้ำหนักของ feature การซ้ำ (บวก = ซ้ำแล้วเสี่ยง spam, ลบ = ซ้ำแล้วดูปกติ) ถ้าข้อความซ้ำที่เป็น spam มีน้อยกว่า 10 แถวจะเตือนว่าโมเดลเรียนเรื่องการซ้ำไม่ได้จริง

## ป้ายข้อมูล (เหลือ 2 ป้าย: `spam` / `normal`)

เดิมมีป้าย `low_quality` เป็นป้ายที่ 3 ตอนนี้ยุบเหลือ 2 ป้าย โดยใช้หลักการติดป้ายด้านล่าง (ใช้ตอนเตรียมข้อมูลเท่านั้น ไม่ได้ใช้ตัดสินในเว็บ):

| ลักษณะข้อความ | ป้าย |
|---|---|
| อีโมจิ/เครื่องหมายล้วน | `spam` |
| สั้น ≤ 3 ตัวอักษร (เช่น `Hi`, `555`) | `spam` |
| ยาวกว่า 3 ตัวอักษรและมีตัวอักษรจริง | `normal` (เว้นแต่เป็นโฆษณา/ชวนติดต่อจริง = `spam`) |

ป้ายเดิมถูกแปลงอัตโนมัติด้วยกฎนี้ (low_quality 126 รายการ → spam 109 / normal 17) ไฟล์ 3 ป้ายเดิมสำรองไว้ที่ `data/to_label.backup_3labels.csv`
ถ้าเปลี่ยนเกณฑ์ความสั้น แก้ `MIN_TEXT_LEN` ใน `ml/text_utils.py` (ใช้กับการแปลงป้ายและ `is_low_quality()` เท่านั้น)
แถวที่ป้ายไม่ใช่ `spam`/`normal` จะถูกข้ามและมีคำเตือนตอนเทรน

## ผลที่วัดได้จากชุดข้อมูลนี้ (1,952 ข้อความที่ไม่ซ้ำ)

ป้าย: normal 1,838 / **spam 114** (อีโมจิล้วน 87, สั้น ≤3 ตัวอักษร 22, โฆษณา/spam จริง 5)

**เทรน (hold-out 20%)**: Precision 0.586 / Recall 0.739 / F1 0.654, CV F1 0.708 ± 0.081

**`evaluate.py` (out-of-fold, ผลก่อนติดป้ายข้อความซ้ำใหม่):**

| วิธี | P | R | F1 | TP | FP | FN |
|---|---|---|---|---|---|---|
| ML ข้อความอย่างเดียว (ทั้งหมด) | 0.674 | 0.781 | 0.724 | 89 | 43 | 25 |
| ML ข้อความ + จำนวนซ้ำ (ทั้งหมด) | 0.647 | 0.789 | 0.711 | 90 | 49 | 24 |
| ML ข้อความอย่างเดียว (เฉพาะข้อความที่ซ้ำ) | 0.875 | 0.737 | 0.8 | 14 | 2 | 5 |
| ML ข้อความ + จำนวนซ้ำ (เฉพาะข้อความที่ซ้ำ) | 0.571 | 0.842 | 0.681 | 16 | 12 | 3 |

ตอนนี้ feature การซ้ำยังไม่ช่วย (ภาพรวม F1 ต่ำกว่าโมเดลที่ดูข้อความอย่างเดียวเล็กน้อย) เพราะป้ายของข้อความซ้ำยังไม่สม่ำเสมอ เช่น ข้อความซ้ำ 15 ครั้งที่เป็นรูปแบบต่างๆ ของ "2026" / "hello" ติดป้าย normal ขณะที่ "." กับ "❤" ที่ซ้ำติดป้าย spam เพราะสั้น ให้ติดป้าย `dup_to_label.csv` แล้วรัน `train.py` / `evaluate.py` ใหม่ จึงจะรู้ว่า feature นี้ช่วยจริงไหม

## ข้อจำกัด (ควรเขียนในรายงานด้วย)

- **spam โฆษณาจริงในข้อมูลมีแค่ 5 รายการ** (spam 114 รายการส่วนใหญ่คืออีโมจิล้วน/ข้อความสั้น) โมเดลจึงเรียนรู้ว่า "ข้อความสั้น/อีโมจิ = spam" เป็นหลัก ไม่ได้เรียนรู้ลักษณะโฆษณาจริง
  (ทดสอบแล้ว: ข้อความชวนแอดไลน์และสล็อตได้คะแนน ML ต่ำ และตอนนี้ไม่มีกฎมาช่วยจับแล้ว)
- ป้าย spam ส่วนใหญ่มาจากหลักข้อความสั้น/อีโมจิตอนติดป้าย ผลวัดจึงสะท้อนว่าโมเดลเรียนหลักนี้ได้ดีแค่ไหน ไม่ใช่ความสามารถจับ spam โฆษณาจริง
- ข้อมูลมาจากหลายวิดีโอ ไม่ใช่ชุดเดียวกับตัวเลขในสไลด์นำเสนอ ให้ตรวจก่อนอ้างตัวเลข
- ไม่รองรับคอมเมนต์ตอบกลับ (replies) นับเฉพาะคอมเมนต์ระดับบนสุด

- **ไม่มีกฎจับ spam โฆษณา** ข้อความชวนแอดไลน์/สล็อตได้ ML ประมาณ 0.20–0.33 (ต่ำกว่า 0.5) จะไม่ถูกจับ จนกว่าจะมีข้อมูล spam จริงเพิ่มแล้วเทรนใหม่
- **feature การซ้ำเรียนรู้ได้เท่าที่ป้ายสอน** ตอนนี้มีข้อความซ้ำในข้อมูลแค่ 83 ข้อความ (spam 19 ซึ่งส่วนใหญ่เป็นอีโมจิ/ข้อความสั้น) ไม่ใช่ spam โฆษณาที่โพสต์ซ้ำ
- ข้อมูลเทรนนับข้อความซ้ำต่อวิดีโอ (เหมือนที่เว็บนับ) แต่เว็บดึงได้ถึง 2,000 คอมเมนต์ ส่วนข้อมูลเทรนมีวิดีโอละ 53–500 ค่าจำนวนซ้ำจึงกระจายต่างกันได้

**ทางปรับปรุง:** ติดป้าย spam โฆษณาจริงให้ได้ 50–100+ รายการ แล้วเทรนใหม่ เพื่อให้โมเดลเรียนรู้ spam จริงมากกว่าข้อความสั้น/อีโมจิ,
ลองโมเดลภาษาไทย (เช่น WangchanBERTa) เมื่อมีข้อมูลมากพอ

## ความปลอดภัย

- **อย่าใส่ API key ในโค้ด/zip** เก็บไว้ใน `.env` เท่านั้น (ไฟล์ `.gitignore` กันไว้แล้ว) ถ้าเคยแชร์คีย์เดิมไปแล้วให้ revoke และสร้างใหม่ใน Google Cloud Console
- `joblib` โหลดไฟล์ `.joblib` ได้เหมือนรันโค้ด **อย่าโหลดโมเดลจากแหล่งที่ไม่น่าเชื่อถือ**
- ไฟล์โมเดลผูกกับเวอร์ชัน scikit-learn (เทรนด้วย 1.9.1) ถ้าเวอร์ชันต่างกันแล้วโหลดไม่ได้ ให้รัน `python ml/train.py` ใหม่
